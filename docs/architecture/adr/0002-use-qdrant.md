# ADR-0002: Adopt Qdrant as the Enterprise Vector Database

## Status

**Accepted**

---

## Date

2025-07-13

---

## Decision Makers

- Enterprise Architect
- Solution Architect
- Technical Lead

---

# Context

The Enterprise AI Orchestration Platform requires a high-performance vector database to support semantic search across enterprise knowledge repositories.

The platform stores embeddings generated by Vertex AI and performs similarity search during Retrieval-Augmented Generation (RAG) workflows.

The vector database must support:

- Large-scale vector storage
- Approximate Nearest Neighbor (ANN) search
- Metadata filtering
- High query performance
- Hybrid retrieval
- Cloud deployment
- REST APIs
- Horizontal scalability
- Open architecture

The solution should integrate seamlessly with Google Cloud Platform while remaining cloud-agnostic for future portability.

---

# Decision

The platform will use **Qdrant** as the primary enterprise vector database.

Qdrant will store vector embeddings, document metadata, and support semantic retrieval for enterprise AI workloads.

The Qdrant service will be deployed on a dedicated Google Compute Engine virtual machine inside a private VPC subnet.

---

# Decision Drivers

The following factors influenced the decision:

- High-performance vector similarity search
- Native metadata filtering
- Hybrid search capability
- Open-source licensing
- Self-managed deployment
- REST API support
- Horizontal scalability
- Production readiness
- Strong Python ecosystem
- Cloud portability

# Alternatives Considered

## Pinecone

### Advantages

- Fully managed service
- Automatic scaling
- Enterprise support
- Minimal operational overhead

### Disadvantages

- Higher operational cost
- Vendor lock-in
- Limited deployment flexibility
- External SaaS dependency

---

## Weaviate

### Advantages

- Rich ecosystem
- GraphQL support
- Native hybrid search
- Extensive integrations

### Disadvantages

- Higher operational complexity
- Larger infrastructure footprint
- More complex configuration

---

## pgvector

### Advantages

- PostgreSQL integration
- Familiar SQL interface
- Simplified deployment

### Disadvantages

- Lower ANN performance
- Limited optimization for large vector datasets
- Reduced scalability for enterprise AI workloads

---

## Vertex AI Vector Search

### Advantages

- Fully managed Google Cloud service
- Tight integration with Vertex AI
- Automatic scaling
- Enterprise reliability

### Disadvantages

- Higher operating cost
- Vendor dependency
- Less deployment flexibility
- Limited portability to other cloud providers

|------|------------|
| VM failure | Automated snapshots and infrastructure as code |

| Performance degradation | Monitor latency and optimize HNSW index configuration |
| Capacity growth | Increase VM resources or migrate to clustered deployment |

---

# Implementation Notes

Qdrant will be deployed on a dedicated Compute Engine virtual machine within a private Google Cloud VPC.

The deployment will support:

- Semantic search
- Metadata filtering
- Hybrid retrieval
- Document chunk storage
- Embedding storage

The FastAPI backend accesses Qdrant using Direct VPC Egress from Cloud Run.
